Four cadences

The official way for a project to raise the floor

Drop .md files into these three folders under .claude/resources/ and the skills read them automatically. If a folder is empty, that section is simply ignored.

design-principles/

  • brand guides, design principles
  • read by /ui-ux-design

domain-knowledge/

  • domain UX patterns, industry rules
  • read by the design and planning skills

coding-standards/

  • your project's own conventions
  • read during implementation
This is the actual channel behind "the safety floor can only be raised." Lowering what the harness sets requires an explicit request — but making it stricter takes nothing more than putting a file in that folder.

Second axis

Reversibility class sets the depth

It is judged by path, never by size. A five-line migration is more dangerous than a four-hundred-line refactor.

Why it works this way — reversible mistakes are cheap and irreversible ones are expensive, so the verification budget is pushed onto the second kind. Attach a review to every change and nobody reads any of them.

P3, and P5 · P6

What the two subagents do

They are not skills — they are separate sessions. They spend none of the main conversation's context, and the tools they hold are the limit of what they can do.

AgentTools it holdsWhat it does, and why only those tools
orangekit-planner Read · Grep · Glob
WebSearch · WebFetch		 Diagnoses which of the four entry states are unmet and returns a concrete implementation plan, exploring the codebase to resolve the ambiguity.
It has no Write. Producing unnecessary documents is structurally impossible. Recording the plan is the main session's job.
orangekit-reviewer Read · Grep · Glob · Bash Audits the real diff independently of the implementer's report. For Irreversible work it fans out across three lenses — correctness, security, reversibility — and decides by majority.
It is read-only. A reviewer that starts fixing things is no longer reviewing; it does not even move files.

Runtime

What actually fires while you build

Two kinds. Hooks are deterministic — the script runs whether or not the model remembers, it costs no tokens, and two of them refuse outright. Rule cards are semantic — when the path matches they enter the context and change the model's judgement.

If a hook itself fails — three states, and where it returns

A blocking device has three states, not two. Folding the third into the first is the most common accident.

StateActionWhy
violation confirmedblock — exit 2States the reason and refuses the tool call
no violation confirmedpass — exit 0—
cannot determine
jq missing · transcript unreadable · offline		pass + say soIt does not block. Fold cannot-determine into blocking and you get a false positive; a false positive makes the user turn the hook off; a hook that is off blocks nothing. Never assert either presence or absence.

Every event supports different fields

  • Stop does not support decision/reason → use continue + systemMessage
  • PreCompact·SessionEnd plain stdout never becomes context → JSON required
  • Unsupported fields are silently ignored — which is why v2's gate never fired

If the hook itself breaks

  • Root cannot be settled → exit 2. It does not keep running against a wrong path
  • Numbers pass through orangekit_num() — never swallowed by || echo 0
  • The session briefing reports a hook survival roll-call every time — a dead hook shows up next session

Failure is declared in the graph

  • 21 nodes return to user-report — the place where the loop ends at a person
  • 2 (verify · cross-check) return to build — back to be fixed
  • The point of the declaration is that failure never disappears quietly

How it judges — the anti-false-positive parts

  • It judges per segment. A command chained with ; && || is judged one segment at a time.
  • Exemptions go by the first token. Exempting on a substring once let doctor.sh …; psql -c "DROP TABLE" through whole.
  • Investigation commands pass. A secret string is fine as long as no file is written.
  • Cannot-determine is not a block. If the input cannot be parsed it says so and passes.

All 27 skills

Every one is attached to a stage in the graph

A skill loads only when it is invoked, so it costs nothing until it is needed. Twenty-one trigger on their own when the situation matches; six wait for a /command. All of them are wired to a stage, which is what lets doctor --usage answer "has this skill ever actually been used?" — and this repository's rule is that nothing gets culled without that measurement.

Only two things ever leave your machine. Every other skill finishes locally. /codex-claude-loop sends plan text or a git diff — never the whole tree — and asks every time. /image-generator sends only the image prompt, never source, but it is billed separately from any ChatGPT subscription — so it shows the price before calling and records your answer in orangekit.config.json instead of asking again. With no API key it does not block: it writes a prompt for you to paste into ChatGPT yourself.

The largest asset in the repo — 154 files, 2 MB

Guides are built from axes, not combinations

Four frontend axes × eight backend axes is 32 combinations. Prebuild all 32 and fixing one thing means editing 32 places. So only 12 axes and 3 seams are prebuilt and the rest is assembled — which is why a stack outside the presets comes out immediately.

Why fixesVariants is mandatory

An axis must declare what it pins down. Leave it out and the axis's guidance gets applied to projects it is wrong for.

A real case — the nextjs axis decides fetching, routing and the server runtime for itself, so the only things it pins are client state and forms: store: zustand · forms: react-hook-form. For a project committed to Redux or Jotai, that pack's state-management section is wrong guidance — which is why the declaration is mandatory and a missing one is a FAIL.

When you get blocked

Three cases, three responses

genuinely dangerous

This is most of them. The message names the pattern you hit — move the secret to an environment variable, narrow the destructive SQL.

false positive

Typically an investigation command that contains a secret string but writes no file. Put the command in a file and run it, or split the segments. And tell Claude it was a false positive — two on the same device makes it a candidate for narrowing that device rather than adding a rule.

cannot determine

This is not a block. It means a tool is missing (jq, playwright) or you are offline, so it passes — but it is never counted as "verified". Neither presence nor absence is asserted.

Don't turn a hook off.
A hook that is off blocks nothing.

When the session gets long — the first "yes" from the top wins

#QuestionIf yes
①Will the next phase use this conversation as its primary source? Is there room in the window?keep going
②Is the current context irrelevant to the next phase?/clear
③Are you handing this to another tool, directory or person?hand off
④Can it be finished without supervision?subagent
⑤Anything else/compact plus an instruction for what comes next
Rule out ① first — the other four all turn the primary source into a summary, and that loss cannot be undone. And make this call when a phase ends. Never mid-phase.
