# react-native pack — symbol ledger

This is the table the gate machine-checks. `provides` is what this pack defines, so **if the seam defines it again that
is a duplicate definition**; `requires` is what this pack consumes but does not define, so **the seam must supply
it**. Library APIs are out of scope for the ledger — only project-local symbols go in it.

The "shape" column carries **the source path · argument names and order · return · what it does on failure · what the
caller must wire up**. Write down only the owner and leave the signature empty and a sibling cluster guesses —
a call that reverses the order of two same-typed arguments is caught by neither TypeScript nor the gate.

## provides — this pack defines them

| symbol | defining file | shape | nature |
| --- | --- | --- | --- |
| `config` · `AppEnv` | config-and-testing.md | **`src/config.ts`** — `AppEnv = 'development' \| 'preview' \| 'production'`. `config: { apiBaseUrl: string; appEnv: 'development' \| 'preview' \| 'production'; trustedWebOrigins: readonly string[] }` (not `as const` — `trustedWebOrigins` is split at runtime). Evaluated at module load (app boot), and when a required value is empty or malformed it **throws** `Error('Environment variable …')` on the spot. It is the **only module** in which `process.env.EXPO_PUBLIC_*` appears, and values are read **with literal keys** like `process.env.EXPO_PUBLIC_API_BASE_URL` (dynamic access is not inlined at build time). `trustedWebOrigins` is `EXPO_PUBLIC_WEB_ORIGINS` (comma-separated) normalized with `new URL(v).origin` | the only module that reads environment values |
| `tokenStore` · `Tokens` | secure-storage.md | **`src/lib/tokenStore.ts`** — `Tokens = { accessToken: string; refreshToken: string \| null; expiresAt: number }` (`expiresAt` is epoch **milliseconds**). `tokenStore.get(): Promise<Tokens \| null>` — when absent, or when **parsing fails, it deletes the item and returns `null`** (never throws). `tokenStore.set(t: Tokens): Promise<void>` — writes one JSON value under one key. `tokenStore.clear(): Promise<void>` — deleting a missing key does not throw. The store option is **pinned** to `keychainAccessible: SecureStore.AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY` (it does not ride a device-migration backup, and a background resend can still read it on the lock screen) | token storage — no plaintext stores |
| `safeInternalHref` | navigation.md | **`src/lib/safeInternalHref.ts`** — `safeInternalHref(raw: string \| null \| undefined, fallback = '/tasks'): string` — the order is **(raw value to validate, fallback path)**. Never throws. **Blocked → `fallback`**: `//host` · `/\host` · `https://host` · `javascript:` · app schemes (`myapp://…`) · control characters · paths like `/..//host` that become protocol-relative after normalization. **Passes**: `/tasks/42?x=1#a` goes through unchanged as `pathname + search + hash`. It does not depend on `window` (RN has no `window.location`) — it builds a `new URL` against the fixed dummy origin `https://app.invalid` and passes only when the resulting origin is the same. Hand the return value only to `router.replace`/`router.push` | path validation for deep links·notification payloads·`returnTo` |
| `newIdempotencyKey` | data-and-offline.md | **`src/lib/idempotency.ts`** — `newIdempotencyKey(): string` — no arguments. Returns `expo-crypto`'s `randomUUID()` as is (`Math.random` is forbidden). Never throws. **The key is generated once, when the mutation is "created" — make a new one on resend and idempotency breaks** | idempotency key |
| `queryClient` · `wireQueryManagers` | data-and-offline.md | **`src/lib/queryClient.ts`** — `queryClient: QueryClient` (a module singleton. `retry` is up to 2 times, only for failures that are not an `ApiError` and for 5xx — the decision duck-types the `status` field of `error` and does not import `ApiError`). `wireQueryManagers(): () => void` — no arguments. Binds `focusManager` to `AppState` ('active') and `onlineManager` to `@react-native-community/netinfo`, and **returns an unsubscribe function**. **Caller's obligation: exactly once, in the root layout's `useEffect(() => wireQueryManagers(), [])`** — call it in the render body and the listeners are torn down and re-registered on every render (`setEventListener` calls the previous cleanup — they do not pile up, but it is waste and the unsubscribe function is lost) | server cache for RN |
| `outbox` · `OutboxOp` · `SendResult` | data-and-offline.md | **`src/offline/outbox.ts`** — `OutboxOp = { key: string; method: 'POST' \| 'PATCH' \| 'DELETE'; path: string; body?: unknown; createdAt: number }`. `SendResult = 'sent' \| 'retry' \| 'drop'`. `outbox.enqueue(op: Omit<OutboxOp, 'key' \| 'createdAt'>): Promise<OutboxOp>` — **`key` is created here with `newIdempotencyKey()`** (the caller does not pass it), and the op is persisted in AsyncStorage in order. `outbox.flush(send: (op: OutboxOp) => Promise<SendResult>): Promise<{ sent: number; kept: number; dropped: number }>` — sends one at a time **in insertion order**, and on `'retry'` **stops right there** (it never sends a later one first — that would flip create→update order). `'drop'` deletes the op and continues. If `send` throws it is treated as `'retry'`. A concurrent call returns the Promise of the flush already in progress (prevents double sends). `outbox.clear(): Promise<void>` — wipes the whole queue. Never throws. **It also stops a flush loop in progress** (a generation counter — the previous user's flush does not send ops that a new user enqueued after the clear). **It must be in the sign-out cleanup order** — leave it out and the previous user's pending mutations are sent with the next user's token. Do not put tokens·secrets in `body` (it is a plaintext store) | offline mutation queue |
| `useOutboxSync` | data-and-offline.md | **`src/offline/useOutboxSync.ts`** — `useOutboxSync(ready: boolean): void` — one argument. Only while `ready` is `true` does it call `outbox.flush(sendOutboxOp)` when coming back online (`onlineManager.subscribe`)·when the app becomes active. While `false` (before the auth verdict·signed out) it sends nothing — sending without a token on a cold start or while signed out produces a 401. **Caller's obligation: `useOutboxSync(status === 'signedIn')` once, in the root layout** | queue send trigger |
| `LoadingView` · `EmptyView` · `ErrorView` | screens-and-states.md | **`src/components/ScreenStates.tsx`** — `<LoadingView label?={string}/>` (owns `accessibilityRole="progressbar"` itself) · `<EmptyView title?={string} action?={ReactNode}/>` (`title` defaults to `'No items to display'`) · `<ErrorView error={unknown} onRetry?={() => void}/>` — the message is built with `toUserMessage(error)`. **Without `onRetry` the retry button disappears** (401·403·404 are those cases) | the three states of a data screen |
| `toUserMessage` | screens-and-states.md | **`src/lib/toUserMessage.ts`** — `toUserMessage(error: unknown): string` — never throws. When `error` is an `ApiError` it branches on `code`; for an unknown code it returns the rate-limit message if `status === 429`, otherwise a generic message. When offline (`onlineManager.isOnline() === false`) the connection message takes precedence. **Never put `error.message` on screen as is** — it leaks the server's internal wording | error → user-facing message |
| `usePermission` · `PermissionKind` · `PermissionState` | permissions-and-devices.md | **`src/device/permissions.ts`** — `PermissionKind = 'location' \| 'camera'`. `PermissionState = 'undetermined' \| 'granted' \| 'denied' \| 'blocked'` (`blocked` = denied **and** `canAskAgain === false`). `usePermission(kind: PermissionKind): { state: PermissionState; request: () => Promise<boolean>; openSettings: () => Promise<void> }` — on mount it only **reads** the current state (it does not ask), and `request()` is called only from a user action. Calling `request()` in `blocked` returns `false` with no OS dialog, so the screen steers to `openSettings()` (opening the Settings app). Never throws | runtime permissions |
| `registerForPushAsync` | permissions-and-devices.md | **`src/device/push.ts`** — `registerForPushAsync(): Promise<string \| null>` — no arguments. An Expo push token string or `null` (permission denied · running in Expo Go (`isRunningInExpoGo()`) · no `projectId` — it does not detect simulators: `expo-device` is not in pkgs, and the install does not block simulator requests). **It does not send the token to the server** — the registration API is a backend contract, so the seam calls it. On Android it creates the notification channel **before** asking for the token. What it throws is a rejection from `getExpoPushTokenAsync` (network · Expo server error · APNs/FCM registration failure), propagated as is | push token issuance |
| `isTrustedOrigin` | webview.md | **`src/webview/trustedOrigin.ts`** — `isTrustedOrigin(url: string, allowed: readonly string[]): boolean` — the order is **(URL to check, list of allowed origins)**. `true` only when the `origin` of `new URL(url)` is **exactly equal** to an element of `allowed`. `false` if it is not `https:` (no development exception — put that in `config.trustedWebOrigins`). A parse failure·empty string·`about:blank` give `false`. No prefix·`includes`·regex comparisons (`https://app.example.evil.com` would pass). Never throws | origin validation for WebView messages·navigation |
| `useNotificationRouting` | navigation.md | **`src/lib/useNotificationRouting.ts`** — `useNotificationRouting(ready: boolean): void` — one argument. **It is the only place notification responses are handled** (other resources call this). While `ready` is `false` (before the auth verdict·signed out) it **preserves the response without consuming it**, and once `true` it validates the payload path with `safeInternalHref`, does `router.push`, then consumes it with `clearLastNotificationResponse()` (so a remount·re-sign-in does not navigate again on the same response). The payload format is a backend contract. **Caller's obligation: `useNotificationRouting(status === 'signedIn')` once, in the root layout** | notification tap → navigate to a screen |
| `isUpdateRequired` | release-and-updates.md | **`src/lib/appVersion.ts`** — `isUpdateRequired(current: string, minSupported: string): boolean` — the order is **(current app version, minimum supported version from the server)**. Compares three numeric `major.minor.patch` parts and returns `true` if `current < minSupported`. **If either side fails to parse it returns `false`** (an undecidable case is not folded into a forced update — one bad server value would lock out every user). Never throws. `current` is read from `Constants.expoConfig?.version`, not from `expo-application` | forced-update decision |
| `renderWithProviders` | config-and-testing.md | **`test/renderWithProviders.tsx`** — `renderWithProviders(ui: ReactElement): Promise<Awaited<ReturnType<typeof render>> & { queryClient: QueryClient }>` — one argument, and **it is async** (RNTL 14's `render`·`fireEvent.press`·`unmount` return Promises — call sites do `await renderWithProviders(...)`). It creates **a fresh `QueryClient` per call** (`retry: false`, `gcTime: Infinity` — so jest does not hang on uncleared timers). It does not use the shared singleton `queryClient` (cache pollution across tests) | test harness |

## requires — the seam must supply them

If the seam fails to fill this list, the pack's examples become unrunnable. The gate checks it after assembly.
**Kind**: `project` must be `export`ed by the seam; `library` is judged by its import binding.

| symbol | kind | shape the pack assumes | why it is a seam concern |
| --- | --- | --- | --- |
| `Task` | project | The domain entity type — the pack reads only `id: string`·`title: string` | the domain vocabulary is set by the contract (`exampleDomain` in `pack.json`) |
| `http` | project | **`src/api/http.ts`** — `http.get<T>(path: string, init?: HttpInit): Promise<T>` · `http.post<T>(path, body: unknown, init?)` · `http.patch<T>(path, body, init?)` · `http.delete<T>(path, init?)` — strips the envelope and returns the data, and throws failures as `ApiError`. `HttpInit = { idempotencyKey?: string; signal?: AbortSignal }` — **when `idempotencyKey` is present it is sent as the `Idempotency-Key` header** (the outbox resend relies on it to prevent double application). The client reads the auth header from `tokenStore` and attaches it — screens never touch tokens | the response envelope·auth refresh flow are functions of the wire contract |
| `ApiError` | project | **`src/api/http.ts`** — `new ApiError(status: number, code: string, message: string)` — **arguments 2 and 3 are both `string`, so only the order distinguishes them: (code, message)**. Carries `status`·`code`·`message`·`requestId?`. The pack only reads `instanceof ApiError` and `status`·`code` | the error code table is a function of the wire contract |
| `Page` | project | `Page<T> = { items: T[]; nextCursor: string \| null }` | the pagination model is a function of the wire contract |
| `useTasksQuery` | project | Shaped like `useTasksQuery(): UseInfiniteQueryResult` — **no arguments**. The pack flattens with `data.pages.flatMap((p) => p.items)` and reads `isPending`·`isError`·`error`·`refetch`·`isRefetching`·`fetchNextPage`·`hasNextPage`·`isFetchingNextPage`. Failures must be normalized to `ApiError` for `ErrorView` to pick a message | the fetching layer is owned by the seam |
| `sendOutboxOp` | project | **`src/api/outboxSend.ts`** — `sendOutboxOp(op: OutboxOp): Promise<SendResult>` — the send function handed straight to `outbox.flush`. Sends `op.key` as `http`'s `idempotencyKey`. **Decision rules**: 2xx and an "already processed with the same key" response → `'sent'` · network failure·5xx·429·**401·408** → `'retry'` (401 means **wait until the token refresh finishes** — `http` attempts the refresh, and if it fails the seam hands off to `signOut`, whose `outbox.clear()` discards the queue. **It does not promise to send after re-sign-in** — pending mutations do not cross an account boundary. Drop it and a single refreshable transient expiry makes the queue vanish) · any other 4xx → `'drop'`. Never throws (if it throws, the outbox treats it as `'retry'`) | which response means "already processed" and which codes are retryable are functions of the wire contract |
| `useAuth` | project | **`src/auth/useAuth.ts`** — `useAuth(): { status: 'loading' \| 'signedIn' \| 'signedOut'; signIn: () => Promise<void>; signOut: () => Promise<void> }` — no arguments. The pack's root layout renders `null` while `status === 'loading'` (the keep-splash package is not in pkgs) and does not redirect before the verdict (reverse the order and the sign-in screen flashes on every cold start). **The cleanup order of `signOut`** (server revocation → `tokenStore.clear()` → `outbox.clear()` → `queryClient.clear()` → store reset) is owned by the seam. Cleaning up a previous token left in the Keychain after an iOS reinstall (first-run detection) is also owned by the seam's boot path | the auth provider (IdP) and token refresh flow are functions of the backend axis |
