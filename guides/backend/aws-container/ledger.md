# aws-container pack — symbol ledger

This is the table the gate machine-checks. `provides` is what this pack defines, so **the seam defining it again is a
duplicate**; `requires` is what this pack consumes but does not define, so **the seam must provide it**.
Library APIs are out of scope — only project-local symbols are listed.

## provides — this pack defines these

**The "shape" column is what keeps parallel authoring from guessing signatures.** Write only the owning file and a sibling
cluster, unable to open it, invents the call shape — measured 2026-08-23 (node-api), another cluster called
`getTask(ownerId, id)` as `getTask(id, ownerId)`, and **because both arguments are `string` neither TypeScript nor
the gate caught it**, turning every single-document read into a 404. In the same measurement
`shutdown(server)` was misread as "the function that installs the signal handlers", producing an example that called it at boot top level,
and the server died in 800ms. So this table records **argument names and order · the return · what it throws on failure ·
and what the caller is obliged to wire**. This pack is especially dangerous: with `dataLayerPolicyEngine: false`
the application layer's ownership filter is the only boundary, and all 5 ownership queries take **`ownerId` as the first
argument** with a second argument that is also `string`. When a shape starts with `name(...)` the gate compares it
against the argument count of the real definition.

| symbol | definition file | shape | role |
| --- | --- | --- | --- |
| `pool` · `db` | data-access.md | `pool: Pool` (pg) · `db = drizzle(pool, { schema })` — both are **module-scope singletons** in `src/db/client.ts` and the only instances in this repository. Do not build them per request. On shutdown, call `await pool.end()` **inside** the SIGTERM handler | pg Pool + Drizzle instance (singleton) |
| `tasks` · `tags` | data-access.md | `tasks = pgTable('tasks', { id uuid PK · ownerId text · title text · body text (default `''`) · archivedAt timestamptz (null = active) · createdAt · updatedAt })` + `tasks_owner_created_idx(ownerId, createdAt, id)` · unique `tasks_owner_title_key(ownerId, title)` · `tags = pgTable('tags', { id uuid PK · ownerId text · taskId uuid → tasks.id cascade · name text })` + `tags_owner_task_idx` · unique `tags_task_name_key(taskId, name)`. **The child table carries `ownerId` directly too** | Drizzle table definitions (the source for migrations) |
| `Task` · `NewTask` | data-access.md | `type Task = typeof tasks.$inferSelect` → `{ id: string; ownerId: string; title: string; body: string; archivedAt: Date \| null; createdAt: Date; updatedAt: Date }` · `type NewTask = typeof tasks.$inferInsert` → the same fields with only `ownerId` and `title` required and `id`, `body`, `archivedAt`, `createdAt` and `updatedAt` optional (DB defaults). Do not hand-write the row type again | Domain types inferred from the tables |
| `findOwnedTask` | data-access.md | `findOwnedTask(ownerId: string, id: string): Promise<Task \| null>` — **the owner is the first argument** (both arguments are `string`, so a swap still compiles). On 0 rows it **returns `null` rather than throwing** — converting to a 404 is the caller's share (the service and handler layers) | Ownership-filtered read |
| `listOwnedTasks` | data-access.md | `listOwnedTasks(ownerId: string, limit: number, cursor?: { createdAt: Date; id: string }, archived?: boolean): Promise<Task[]>` — the owner is the first argument. **It returns up to `limit + 1` rows** (to decide whether a next page exists — the caller trims). `archived` unset = active rows only, `true` = archived rows only. 0 rows is an empty array, not an exception | Cursor list read |
| `updateOwnedTask` | data-access.md | `updateOwnedTask(ownerId: string, id: string, patch: UpdateTaskInput): Promise<Task \| null>` — the owner is the first argument and `id` the second (both `string`). `patch` accepts only the parsed request type — pass a `Partial<NewTask>` and `ownerId` rides into the `set`, **handing the row to someone else**. On 0 rows it **returns `null` rather than throwing** | Mutation that checks affected rows |
| `deleteOwnedTask` | data-access.md | `deleteOwnedTask(ownerId: string, id: string): Promise<number>` — the owner is the first argument. **It returns the number of deleted rows, not the row.** `0` is a normal return and that is when the caller makes a 404 — discard the return and a 204 goes out for someone else's `id` too | Mutation that checks affected rows |
| `replaceTaskTags` | data-access.md | `replaceTaskTags(ownerId: string, taskId: string, names: string[]): Promise<(typeof tags.$inferSelect)[] \| null>` — the owner is the first argument. One `db.transaction` finishes the ownership check → deleting the existing tags → reinserting. The return has three branches: not owned or absent → `null`, `names` empty → `[]`, otherwise → the array of inserted `tags` rows. Do not pass `tx` outside the callback | Transactional mutation |
| `env` · `publicEnvKeys` | input-validation.md | `env: z.infer<typeof EnvSchema>` — the validated `process.env` (17 public keys + 2 secret keys). **It validates at module load and calls `process.exit(1)` on failure**, so the import alone can kill the process (tests fill `testEnv` first) · `publicEnvKeys: string[]` = `Object.keys(PublicEnv.shape)` — the basis of the log allowlist, and `DATABASE_URL` and `AUTH_STATE_SECRET` are not in it | The single entry point for validated environment variables |
| `CreateTaskInput` · `UpdateTaskInput` | input-validation.md | `CreateTaskInput` = `TaskFields.extend({ body: … .default('') })` → parse result `{ title: string; body: string }` (`body` is `''` when unset) · `UpdateTaskInput` = `TaskFields.partial().refine(at least one key)` → `{ title?: string; body?: string }`, and **an empty object is refused**. Both are of the `strictObject` family, so they refuse unknown keys, and **the value and a same-named type are exported together**, so `CreateTaskInput` is used as-is in type position | Request DTOs |
| `ListTasksQuery` · `TaskIdParam` | input-validation.md | `ListTasksQuery` → after parsing, `{ limit: number (1-100, default 20); cursor?: string (≤200, base64url `"<iso>\|<uuid>"`); archived?: boolean }` — the source is a query string, so this is the type **after** conversion through `coerce` and `stringbool` (not `z.input`) · `TaskIdParam` → `{ id: string }` (uuid validated). Both export the value and a same-named type together | Query and path DTOs |
| `jsonBody` | input-validation.md | `jsonBody<T extends ZodType>(c: Context, schema: T): Promise<z.infer<T>>` — the argument order is (context, schema) and **it is `async`, so `await` is required**. Failure is a throw, not a return value: a non-JSON body gives `AppError(400, 'VALIDATION_FAILED')` (no `details`) and a schema violation `AppError(400, 'VALIDATION_FAILED')` + `fieldErrors` | Parsing helper |
| `queryParams` | input-validation.md | `queryParams<T extends ZodType>(c: Context, schema: T): z.infer<T>` — **synchronous** (do not `await` it). It parses `c.req.query()`. On a violation it throws `AppError(400, 'VALIDATION_FAILED')` | Parsing helper |
| `pathParam` | input-validation.md | `pathParam<T extends ZodType>(c: Context, schema: T): z.infer<T>` — **synchronous**. It parses `c.req.param()`. On a violation it throws `AppError(400, 'VALIDATION_FAILED')` | Parsing helper |
| `ObjectStorage` | portability-boundaries.md | **`src/storage/index.ts`** — `interface ObjectStorage { put(key: string, body: Uint8Array, contentType: string): Promise<void>; presignGet(key: string, expiresInSec: number): Promise<string> }` — `expiresInSec` is in **seconds**. It is the only storage type app code imports, and the only thing that knows the AWS SDK is the implementation (`src/storage/s3.ts`). The server makes the storage key (`tasks/<ownerId>/<uuid>`) | Storage port (the only type the app sees) |
| `s3Storage` | portability-boundaries.md | **`src/storage/s3.ts`** — an `ObjectStorage` implementation. It reads `env.S3_BUCKET` and `S3_ENDPOINT`, and **`presignGet`'s `expiresInSec` is in seconds**. App code depends on the `ObjectStorage` type, not on this symbol — which implementation to use is decided at the assembly point | S3 adapter |
| `log` | portability-boundaries.md | `log.info(fields: Record<string, unknown>): void` — `debug`, `info`, `warn` and `error` share the same signature. **The argument is an object, not a string**, and the message goes in the `msg` field (`log.info({ msg: 'listening', port })`). Anything below `env.LOG_LEVEL` is not emitted. Do not put tokens, `DATABASE_URL`, PII or object spreads (`{ ...user }`) in it | Structured logging |
| `logBootConfig` | portability-boundaries.md | `logBootConfig(): void` — no arguments. **The caller wires it**: call it **exactly once** right after `serve()` in `src/index.ts`. It prints only the keys in `publicEnvKeys`, so a secret cannot structurally get in | Structured logging |
| `requestContext` | portability-boundaries.md | `requestContext = createMiddleware<AppEnv>(async (c, next) => …)` — **not a function you call but a Hono middleware you wire**: `app.use(requestContext)` **before** the route registrations. It sets `c.set('requestId', …)` and the `x-request-id` response header, and emits one access log line after `await next()`. An incoming `x-request-id` is reused only when it passes `/^[\w-]{1,64}$/` | Structured logging |
| `testEnv` | testing.md | `testEnv: Record<string, string>` — **a constant object whose values are all strings** (the env schema does the conversion). Both vitest configs share it as `test: { env: testEnv }`. `globalSetup` runs outside the workers, so the integration config file needs **an additional** `Object.assign(process.env, testEnv)` at the very top — omit it and `@/config/env` ends Vitest with `exit(1)` and no message. `OIDC_ISSUER` and `OIDC_AUDIENCE` have to match the test token's `iss` and `client_id` | Test environment variable fixture |

## requires — the seam must provide these

**Distinguish the kind.** `project` means the seam must `export` it; `library` comes from a package the seam
chose, so it is judged by whether the name appears in an import statement. Every requires in this pack is
a project symbol.

| symbol | kind | shape the pack assumes | why it belongs to the seam |
| --- | --- | --- | --- |
| `app` | project | The Hono app instance (the sub-app mount point) | The route assembly order is a function of the combination |
| `AppEnv` | project | The type binding for `c.get`/`c.set` | What rides on the context depends on the auth method |
| `AppError` | project | `new AppError(status: number, code: string, message: string, details?: Record<string, string[]>)` — **the argument order is (numeric `status`, string `code`, string `message`)** and **the last two arguments are both `string`, so a swap still compiles** — swapped, a human sentence goes out in the wire code slot. `code` is the constant a client branches on (the values this pack uses: `VALIDATION_FAILED`·`UNAUTHENTICATED`·`NOT_FOUND`·`FORBIDDEN`) and `message` is a sentence for people. The fourth, `details`, is optional and the pack puts `z.flattenError(err).fieldErrors` in it. It exposes the fields `status`, `code`, `message` and `details` directly so `onError` can move them into the envelope. Exported from `@/http/errors` | The error code table is a function of the wire contract |
| `onError` | project | Global error → envelope mapping | The response envelope is a function of the wire contract |
| `requireAuth` | project | Auth middleware | How the token is verified is a function of the backend auth dimension |
| `AuthUser` | project | The verified principal (`sub` and so on) | Same as above |
| `safeReturnPath` | project | `safeReturnPath(input: string): string` — one argument, **synchronous and it does not throw**. A refusal is not an exception but **a fallback return of `'/'`**, so the return value must be what the redirect uses (use the original input and the block is void). What it blocks and turns into `'/'`: the scheme-relative `//evil.com` · the backslash `/\evil.com` (browsers treat it as `/`) · the absolute URL `https://evil.com` · anything with a scheme such as `javascript:` · the path escape `/..//evil.com` · a control-character injection `/tasks\n/x`. What it passes: an internal path starting with a single `/` and its query (`/tasks/42?tab=1` → verbatim). Exported from `@/http/return-path` | The login flow is a contract with the frontend axis |
| `isUniqueViolation` | project | SQLSTATE → domain error detection | The 409 mapping is a function of the wire contract |
| `insertTask` | project | `insertTask(ownerId: string, input: CreateTaskInput): Promise<Task>` — **the owner is the first argument**. That is the convention of this pack's query layer, and all 5 siblings in `provides` (`findOwnedTask(ownerId, id)`·`listOwnedTasks(ownerId, limit, …)`·`updateOwnedTask(ownerId, id, patch)`·`deleteOwnedTask(ownerId, id)`·`replaceTaskTags(ownerId, taskId, names)`) use the same order — **only the second argument's name varies between `id` and `taskId`; that the first argument is the owner has no exception.** The second argument is not an id but **the parsed `CreateTaskInput`** (`{ title, body }`), and `ownerId` does not go into that object — put it there and the client decides the owner. It returns the single inserted row (`row.id` is used) and, unlike its siblings, **does not return `null`**. It does not swallow a duplicate title but **throws SQLSTATE `23505` as-is** — converting to 409 is the caller's share, using `isUniqueViolation`. Exported from `@/db/queries/tasks`, the same module as its sibling queries | **Asymmetry**: the read, update and delete queries are owned by the pack while only create lives in the seam (the complete example). It was inherited from the original `react-aws-backend-guide` and was not created by this relayout |
