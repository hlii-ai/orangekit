# gcp-serverless pack — symbol ledger (L0 declaration)

This is the contract the main session declares before authoring. It is the only device that keeps duplicate definitions and **signature
guessing** from appearing when clusters are split and written in parallel.

**The "shape" column is mandatory.** Assign only the owning file and leave the shape empty and a sibling cluster
guesses the signature — measured (node-api), one cluster called `getTask(ownerId, id)` as `getTask(id, ownerId)`,
and since both arguments were `string` neither the type check nor the gate caught it, so every single-item lookup returned
404. Write the argument **order** · the return · what it throws on failure · **what the caller has to wire up**, together.

**The "definition file" is document ownership, not a code path.** So **nail the source path down** in the shape
column — measured in firebase, one cluster assumed `src/firestore/model.ts` (a flat root) while the other
two assumed `functions/src/…`, and the relative imports of the assembly did not resolve. **The gate passes a symbol as long as
it is defined somewhere in the pack.**

**The three spots that are especially dangerous in this pack:**

1. **`ownerId` and `taskId` are both `string`.** Swap the order and TypeScript will not catch it.
   Fix the order **`ownerId` → `taskId`** across every function
2. **There is no session or transaction argument.** The Firestore client is a process-wide single instance at
   module top level, so repository functions **do not take it as an argument** — only a function that needs a
   transaction takes a `Transaction`, and that fact goes into the shape
3. **The obligation to consume a field.** Even with a matching signature, not using the *contents* of an argument produces the
   same class of fatal defect (measured in aws-serverless: the create function dropped `status` and hard-coded it)

## provides — this pack defines them

| symbol | definition file | shape | kind |
| --- | --- | --- | --- |
| `settings` | input-validation.md | **`src/settings.ts`** — environment values parsed with zod. `GCP_PROJECT_ID` · `IDENTITY_PLATFORM_PROJECT_ID` · `PORT` (injected by Cloud Run; default 8080) · `LOG_LEVEL` · `NODE_ENV` · `FIRESTORE_EMULATOR_HOST?`. **It parses at module top level** — a validation failure has to be a boot failure (blowing up at request time leaves a half-alive container). **It is the only file that reads the environment** | validated environment values |
| `TaskStatus` | input-validation.md | **`src/schemas/task.ts`** — `z.enum(['open', 'done'])`. **The values are the lowercase `'open'`·`'done'`.** What the wire, the Firestore document, and test assertions use is the **value**, not the member name — leaving this cell empty led a sibling cluster to assert `=== 'DONE'`, so the block-proof test was permanently red (measured in fastapi) | status enum |
| `Task` | input-validation.md | **`src/schemas/task.ts`** — **it is both a runtime zod schema and a type** (declaration merging): `export const Task = z.object({ id, ownerId, title, status, createdAt })` + `export type Task = z.infer<typeof Task>`. **Export only the type and `taskConverter` does not compile** — its contract requires `Task.parse(...)`. `TaskCreate`·`TaskQuery` are written as `z.object` while this cell alone was read as a plain object type (reported by C2). `id` is **the document ID, not a document field** — the converter fills it from the snapshot. `ownerId` **is also stored as a document field** (the query filter reads it) | domain type |
| `TaskCreate` | input-validation.md | **`src/schemas/task.ts`** — `z.object({ title: z.string().min(1).max(200), status: TaskStatus.default('open') })`. `.strict()` — it **rejects** unknown keys | create body |
| `TaskUpdate` | input-validation.md | **`src/schemas/task.ts`** — a partial of `TaskCreate`. **Do not put a default on an optional field** — with one, a partial update overwrites fields that were never sent. An empty object is rejected | update body |
| `TaskQuery` | input-validation.md | **`src/schemas/task.ts`** — `{ limit: number(1–100, default 20); cursor?: string; status?: TaskStatus }`. `.strict()` — **if an unknown query parameter passes silently, a list with the filter ignored is returned as a normal response** | list query |
| `fieldErrors` | input-validation.md | **`src/schemas/errors.ts`** — `(err: z.ZodError) => Record<string, string[]>` — joins `path` with dots and uses it as the key. **Does not strip array indices** — once which item was wrong disappears, the form cannot attach the error. **It must handle the case where `path` is an empty array**: that is what zod 4's `unrecognized_keys` (= a `.strict()` violation, the very thing this pack enforces by policy) does (measured in the pilot). Join an empty array as-is and the key becomes `""` — fold it into a fixed key such as `_root` | field errors |
| `ROOT_FIELD` | input-validation.md | **`src/schemas/errors.ts`** — `'_root'`. The key `fieldErrors` folds **issues whose `path` is an empty array** into (zod 4's `unrecognized_keys`, a failed `refine`). **Export it as a constant** — if the seam hard-codes the string, only one side changes and the form cannot attach the error | fixed key |
| `firestore` | data-access.md | **`src/firestore/client.ts`** **this is the only definition** — a `Firestore` instance. **Built once at module top level** (Cloud Run is a resident process — build it per request and gRPC channels pile up). If `settings.FIRESTORE_EMULATOR_HOST` is set it connects to the emulator | client |
| `taskConverter` | data-access.md | **`src/firestore/converter.ts`** — `FirestoreDataConverter<Task>` — `toFirestore` **removes `id` from the document data** (store it alongside the document ID and the two diverge). **To use it on a `CollectionReference<Task>` you pass a complete `Task`** — the shape is `ref.create(task)`, where you fill in `id` and the converter then strips it (measured by C2; the type check passes), and `fromFirestore` fills `id` from `snap.id`. **`fromFirestore` re-parses the schema** — documents can change outside the code, so they are not trusted input | converter |
| `tasksRef` | data-access.md | **`src/firestore/tasks.ts`** — `CollectionReference<Task>` — `firestore.collection('tasks').withConverter(taskConverter)`. **No other file builds a reference that omits `withConverter`** — build one and only that path receives raw documents and the types lie | collection reference |
| `listTasks` | data-access.md | **`src/firestore/tasks.ts`** — `(ownerId: string, q: TaskQuery) => Promise<{ items: Task[]; nextCursor: string \| null }>` — **`where('ownerId', '==', ownerId)` is the only boundary.** The ordering is both `('createdAt', 'desc')` and `('__name__', 'desc')` (documents with identical timestamps are lost or duplicated at the page boundary) | list |
| `getTask` | data-access.md | **`src/firestore/tasks.ts`** — `(ownerId: string, taskId: string) => Promise<Task \| null>` — **both arguments are `string`, so the order is everything.** After reading the document you **must** check `doc.ownerId === ownerId` — read by document ID alone and it hands over someone else's task. Missing or someone else's gives `null` (not an exception) | single item |
| `createTask` | data-access.md | **`src/firestore/tasks.ts`** — `(ownerId: string, data: TaskCreate) => Promise<Task>` — **carries over both `title` and `status` from `data`.** Hard-coding `status` silently discards what the client sent (fatal, measured in aws-serverless). `ownerId` comes only from the argument and **never from the body**. **`createdAt` is `Timestamp.now()` (client time)** — this function returns a `Task` **synchronously**, so `FieldValue.serverTimestamp()` cannot be used. Switching to server time changes `Task` and this return contract together (reported by C2) | create |
| `updateTask` | data-access.md | **`src/firestore/tasks.ts`** — `(ownerId: string, taskId: string, patch: TaskUpdate) => Promise<Task>` — **read inside a transaction, confirm ownership, then write.** Split the confirmation from the write and you overwrite a document whose owner changed in between. Missing or someone else's gives `AppError('NOT_FOUND', …)` — **not `FORBIDDEN`** (that leaks existence) | update |
| `deleteTask` | data-access.md | **`src/firestore/tasks.ts`** — `(ownerId: string, taskId: string) => Promise<void>` — **`delete()` succeeds even on a missing document.** Confirm existence and ownership inside a transaction, then delete. Without the check, a request to delete someone else's also returns 204 | delete |
| `encodeCursor` | data-access.md | **`src/firestore/cursor.ts`** — `(createdAt: Timestamp, taskId: string) => string` — an opaque string. Do not turn the internal sort key into a wire contract | cursor encoding |
| `decodeCursor` | data-access.md | **`src/firestore/cursor.ts`** — `(cursor: string) => { createdAt: Timestamp; taskId: string }` — failure is `AppError('VALIDATION_FAILED', …)`. **A cursor is not trusted input** | cursor decoding |
| `isNotFound` | error-handling.md | **`src/firestore/errors.ts`** (it knows nothing about HTTP — put it under `http/` and the repository drags in an HTTP module) — `(err: unknown) => boolean` — decides on gRPC **code 5**. Matching on message strings breaks with the SDK version | absence detection |
| `isAlreadyExists` | error-handling.md | **`src/firestore/errors.ts`** — `(err: unknown) => boolean` — gRPC **code 6** | duplicate detection |
| `isFailedPrecondition` | error-handling.md | **`src/firestore/errors.ts`** — `(err: unknown) => boolean` — gRPC **code 9**. **A composite query with no index dies with this code** — that is a developer mistake, not a user input problem, so folding it into a 4xx makes the cause disappear | precondition-violation detection |
| `isInvalidArgument` | error-handling.md | **`src/firestore/errors.ts`** — `(err: unknown) => boolean` — gRPC **code 3**. **A document over 1 MiB is rejected with this code** (measured by C2: `longer than 1048487 bytes`). Fold it into `INTERNAL` and it looks like a "server error" when in fact **the input exceeded a limit**, so `VALIDATION_FAILED` is correct | limit-violation detection |
| `isAborted` | error-handling.md | **`src/firestore/errors.ts`** — `(err: unknown) => boolean` — gRPC **code 10** (transaction contention). The SDK has already retried, so **reaching here means the retries were exhausted** | contention detection |
| `ERROR_STATUS` | error-handling.md | **`src/http/errors.ts`** — `Record<string, number>` — **the only mapping table** from domain code to HTTP status. **The values are frozen here**: `VALIDATION_FAILED`=**422** · `UNAUTHENTICATED`=401 · `FORBIDDEN`=403 · `NOT_FOUND`=404 · `CONFLICT`=409 · `INTERNAL`=500. **422 is especially dangerous** — a sibling cluster assuming 400 diverges silently and only the tests go red (the same reason `TaskStatus` was nailed down to its values). The gRPC mapping is decided here too: **3→`VALIDATION_FAILED` · 5→`NOT_FOUND` · 6→`CONFLICT` · 9→`INTERNAL` (a developer mistake. Fold it into a 4xx and the cause disappears) · 10→`CONFLICT`** (merging 6 and 10 into one domain code is deliberate — from outside, both mean "try again now") | status mapping |
| `statusFor` | error-handling.md | **`src/http/errors.ts`** — `(code: string) => number` — `ERROR_STATUS[code] ?? 500`. **It is the seam's only route to a status.** Leave subscript access open and a code absent from the table puts `undefined` where the status goes, the runtime error folds back into a 500, and the cause disappears — yet "use it with `?? 500` attached" cannot be enforced by policy (the forbidding regex blocks the safe shape along with the rest; measured in the pilot). **Giving an accessor and forbidding the subscript is the only enforceable shape** | status lookup |
| `toAppError` | error-handling.md | **`src/http/errors.ts`** — `(err: unknown) => AppError` — the error handler **must call it first**. Everything unknown folds into `INTERNAL` (the original message carries the project ID and document paths) | normalization |
| `verifyIdToken` | identity-tokens.md | **`src/identity/verify.ts`** — `(token: string) => Promise<IdTokenClaims>` — **it is asynchronous.** It verifies `iss === 'https://securetoken.google.com/' + settings.IDENTITY_PLATFORM_PROJECT_ID` · `aud === settings.IDENTITY_PLATFORM_PROJECT_ID` · `exp`·`iat`, and checks the signature against the JWKS. **Every failure folds into the single `AppError('UNAUTHENTICATED', …)`** — distinguishing expiry, signature mismatch, and issuer mismatch hands the attacker a diagnosis | token verification |
| `IdTokenClaims` | identity-tokens.md | **`src/identity/verify.ts`** — at minimum `{ sub: string; email?: string; email_verified?: boolean }`. **The subject is `sub`** — `email` can change, so do not use it as the ownership key | claims type |
| `jwks` | identity-tokens.md | **`src/identity/verify.ts`** **this is the only definition** — the return of `createRemoteJWKSet`. **Built once at module top level** — build it per request and there is no cache, so every request round-trips to Google (Cloud Run is a resident process, so this cache really does live) | JWKS cache |
| `createApp` | project-structure.md | **`src/app.ts`** — `() => Hono` — **it takes no request.** It only mounts routers, calls `installErrorHandlers(app)` (the seam), and registers `/healthz`. It attaches `apiRouter` (the seam) at `/api` | app assembly |
| `startServer` | project-structure.md | **`src/main.ts`** — `() => ServerType` — binds to `settings.PORT` with `serve()` from `@hono/node-server` (it does not read the environment directly). **It binds to `0.0.0.0`** — bind to `localhost` and it is unreachable from outside the container, so the deploy dies at the health check | boot |
| `shutdown` | project-structure.md | **`src/main.ts`** — `(server: ServerType) => Promise<void>` — **the function that performs the drain.** It stops new connections, waits for in-flight requests, then calls `firestore.terminate()`. **What the caller has to wire up: call it *inside* a `process.on('SIGTERM', …)` handler.** Called at the top level, the container exits right after boot (fatal, measured in node-api). Cloud Run gives **10 seconds** after SIGTERM | shutdown |
| `log` | project-structure.md | **`src/obs/log.ts`** — `(level: 'info' \| 'warn' \| 'error', message: string, fields?: Record<string, unknown>) => void` — writes **one line of JSON to stdout**. Cloud Logging reads the `severity` key as the severity, so emit **`severity`** rather than `level`. Do not put secrets, tokens, or whole documents into the fields. **The value set of `settings.LOG_LEVEL` is the same as these three values** — the ledger not fixing that nearly led each cluster to assume a different set (reported by C3) | structured logging |
| `appFetch` | testing-and-deploy.md | **`test/helpers.ts`** — `appFetch(app: Hono, path: string, init?: RequestInit): Promise<Response>` — drives the app directly with `app.request()`, **without a network**. **It has to be an `async` function** — the return of `app.request()` is `Response | Promise<Response>` (hono 4.13's `hono-base.d.ts`), and a synchronous handler really does produce a non-Promise `Response`, so returning it from a non-`async` function is `TS2322` under strict (measured by C4) | test invocation |
| `withEmulator` | testing-and-deploy.md | **`test/helpers.ts`** — `(fn: () => Promise<void>) => Promise<void>` — empties the collection per test. **Without the reset, the next test sees the previous test's documents** | test isolation |

> **Ownership of a test file follows the resource.** `test/helpers.ts` (`appFetch`·`withEmulator`) is owned by `testing-and-deploy.md`, and **a unit test file is owned by the resource that owns its subject** — `test/errors.test.ts` by `error-handling.md`, `test/schemas.test.ts` by `input-validation.md`, **`test/tasks.repo.test.ts` by `data-access.md` (it calls the repository directly), and `test/tasks.http.test.ts` by `testing-and-deploy.md` (it goes through `appFetch`)**. An unassigned path means two clusters author the same file — which is exactly how `test/tasks.test.ts` split (audit C) — `test/errors.test.ts` is `error-handling.md` and `test/schemas.test.ts` is `input-validation.md`. It existed only in the `PACK.md` tree and not in the ledger, so two clusters nearly wrote the same file (reported by the pilot).

## requires — the seam has to provide them

`project` has to be defined by the seam; `library` is decided by whether the name appears in an
import statement. **Write the call signature for any symbol the pack calls** — without it, the seam
guesses the argument order (the gate blocks it with a FAIL).

| symbol | kind | shape the pack assumes | why it is a seam |
| --- | --- | --- | --- |
| `AppError` | project | `new AppError(code: string, message: string, details?: Record<string, string[]>)` — **both leading arguments are `string`, so the order is everything (the code comes first).** The code table must include: `VALIDATION_FAILED` · **`UNAUTHENTICATED`** (`verifyIdToken` throws it — if it is missing, a 401 goes out as a 500) · `FORBIDDEN` · `NOT_FOUND` · `CONFLICT` · `INTERNAL`. **Goes in `src/errors.ts`** — **not** under `src/http/`: the repository and the cursor throw it, so putting it there makes the data layer drag in an HTTP module | the error code table and the envelope shape are a function of the wire contract |
| `installErrorHandlers` | project | `installErrorHandlers(app: Hono): void` — hangs `app.onError` and `app.notFound`. **Normalize with `toAppError` first and decide the status with `statusFor(appErr.code)`** — subscript access on `ERROR_STATUS` is blocked in the seam with a FAIL by policy `seam-status-lookup`. If the ledger prescribes a forbidden shape, a seam that follows it inevitably fails after assembly (audit C). `createApp` calls it | the response envelope is a function of the wire contract |
| `currentUser` | project | a Hono middleware — `MiddlewareHandler`. It extracts the credential, **hands it to `verifyIdToken` (provided by the pack)**, and plants the result with `c.set('user', …)`. Failure is `AppError('UNAUTHENTICATED', …)`. **Goes in `src/http/auth.ts`.** Routers obtain the subject only through this middleware — if even one router parses the token itself, there are two boundaries | **how the token arrives** (bearer header vs session cookie) is a function of the combination |
| `AuthUser` | project | at minimum `{ id: string; roles: string[] }` — **`id` is the `sub` of the ID token and that becomes `ownerId`** | same as above |
| `authFor` | project | `authFor(ownerId: string, roles?: string[]): AuthUser` — builds the subject a test passes when replacing `currentUser`. **Synchronous** | the claim shape is a function of the authentication method |
| `apiRouter` | project | `Hono` — collects the domain routers, and `createApp` attaches it with `app.route('/api', apiRouter)` | the route layout is a function of the combination |
