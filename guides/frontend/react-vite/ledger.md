# react-vite pack — symbol ledger

This is the table the gate machine-checks. `provides` is what this pack defines, so **if the seam defines it again that
is a duplicate definition**; `requires` is what this pack consumes but does not define, so **the seam must supply
it**. Library APIs are out of scope for the ledger — only project-local symbols go in it.

From v3.35.0 the HTTP client · complete example · auth adapter live inside the pack (standard contract `http-standard`).
A row whose defining file is `auth-and-session.md` is a **variant file** — every directory under `variants/auth/<method>/`
must define that row's symbols in the same shape, and the gate checks it per combination.

## provides — this pack defines them

The "shape" column carries the **call contract** together with the owning file. Write down only the owner and leave the
signature empty and a sibling cluster, unable to open the definition, **guesses.** In the 2026-08-23 parallel-authoring
measurement two critical defects came out of exactly this hole — a call that reversed the **order** of two same-typed
arguments was caught by neither TypeScript nor the gate (every single-record lookup 404'd), and an example that mistook
the function that *performs* the drain for the one that *wires* it up sat at boot top level and killed the server in 800ms.
So this column records the argument names and order · return · **what it throws on failure** · what the caller must wire up.

| symbol | defining file | shape | nature |
| --- | --- | --- | --- |
| `cn` | styling.md | **`src/lib/cn.ts`** — `cn(...inputs: ClassValue[]): string` — variadic. The order is `clsx` → `twMerge`, so **the later conflicting class wins** (`px-4 px-6` → `px-6`). Never throws | class-merge utility |
| `ButtonProps` | styling.md | `ComponentPropsWithoutRef<'button'> & { variant?: 'primary' \| 'secondary' \| 'danger' \| 'ghost'; size?: 'sm' \| 'md' \| 'lg' }` — both fields are optional and `Button` supplies the defaults. The unions are derived from `keyof typeof variants`/`keyof typeof sizes`, so adding a key to a map widens the type automatically | variant type |
| `Button` | component-patterns.md | `<Button variant?='primary' size?='md' className? {...button attributes}>{children}</Button>` — props are `ButtonProps`. This component alone owns the height·spacing·typography tokens. `className` is the last argument to `cn()` so the call site wins, but **only for positional adjustments (`mt-4`·`w-full`)** — a convention, not an enforcement | shared UI |
| `Field` | component-patterns.md | `<Field label={string} htmlFor={string} error?={string} hint?={string}>{input element}</Field>` — `label`·`htmlFor`·`children` required. **Caller's obligation: the child input's `id` must equal `htmlFor`** for the label·`aria-describedby` wiring to hold. When `error` is present, `hint` is not rendered | shared UI |
| `DataTable` | component-patterns.md | `<DataTable rows={T[]} columns={Column<T>[]} empty?={ReactNode}/>` — generic over `T extends { id: string }` (row.id is the key). `Column<T> = { key: string; header: ReactNode; cell: (row: T) => ReactNode; className?: string }`. When `rows` is empty it renders `empty` and nothing else | shared UI |
| `PageShell` | component-patterns.md | `<PageShell title={ReactNode} actions?={ReactNode}>{children}</PageShell>` — it has slots and nothing else. It knows nothing of fetching·routing·domain types (if it does, that is the ❌ example in §3) | shared layout |
| `EmptyState` · `EmptyStateProps` | loading-error-states.md | **`src/components/common/EmptyState.tsx`** — `EmptyStateProps = { title?: string; description?: string; action?: ReactNode }` — every field optional. `title` defaults to `'No items to display'`. Without `action`, the button area itself is not rendered | empty state |
| `ErrorState` · `ErrorStateProps` | loading-error-states.md | **`src/components/common/ErrorState.tsx`** — `ErrorStateProps = { title?: string; message?: string; error?: unknown; onRetry?: () => void }` — every field optional. `title` defaults to `'Something went wrong'`, and an empty `message` is filled from `toUserMessage(error)`. **Omit `onRetry` and the retry button disappears** — 403·404·429 are those cases. When `error` is an `ApiError`, the `requestId` is shown alongside | error state |
| `ListSkeleton` | loading-error-states.md | `<ListSkeleton rows={number}/>` — `rows` is **required** (no default). It owns `role="status"` and `aria-label` itself, so the call site does not add them again | loading state |
| `toUserMessage` | loading-error-states.md | `toUserMessage(error: unknown): string` — never throws. For an `ApiError` it branches on `error.code`; for an unknown code it uses the rate-limit wording when `status === 429` and otherwise `error.message` as is. When it is not an `ApiError`, a generic message | error → user-facing message |
| `useUiStore` · `UiState` | state-management.md | **`src/stores/uiStore.ts`** — `useUiStore(selector: (s: UiState) => T): T` — during render only as a hook; outside render, `useUiStore.getState()`/`.setState()`/`.subscribe(fn)` (which returns an unsubscribe function). Selecting several fields in one selector requires `useShallow` (without it, infinite re-renders). `UiState` holds state and actions in one object and **must include `reset(): void`** — the logout path calls it | global client state |
| `createSidebarSlice` · `SidebarSlice` | state-management.md | **`src/stores/slices/sidebar.ts`** — `createSidebarSlice: StateCreator<SidebarSlice & FilterSlice, [], [], SidebarSlice>` — the place that combines them passes all three of `(set, get, store)` but the body uses only `set`. `SidebarSlice = { isSidebarOpen: boolean; toggleSidebar: () => void }`, with `isSidebarOpen` starting at `true`. The first type argument must be the **combined whole state** for other slices to be visible from `get()` | store slice |
| `createFilterSlice` · `FilterSlice` | state-management.md | **`src/stores/slices/filter.ts`** — `createFilterSlice: StateCreator<SidebarSlice & FilterSlice, [], [], FilterSlice>` — the body uses `(set, get)`. `FilterSlice = { savedFilters: string[]; addFilter: (name: string) => void }`, with `savedFilters` starting at `[]`. `addFilter` **silently ignores a duplicate name** (it neither throws nor reports) | store slice |
| `clearClientState` | state-management.md | **`src/stores/clearClientState.ts`** — `clearClientState(): void` — no arguments. It clears **the client stores only** (`useUiStore.getState().reset()`). **Discarding the server cache (QueryClient) and controlling the ordering belong to the logout procedure — do not put them in this function.** When a store is added, add one `reset()` line to this function | resets client state on logout |
| `router` | routing.md | `router: ReturnType<typeof createBrowserRouter>` — the app's **single instance**, passed only to `<RouterProvider router={router}/>`. Keep the tree in one file and put `path: '*'` last among the top-level children. It does not use `loader`/`action` — the single owner of server state is TanStack Query | route tree |
| `RootLayout` | routing.md | `<RootLayout/>` — no props. It draws the header and `<main>` and owns the `<Outlet/>` slot. Used only as the `element` of the top-level route | global shell |
| `RequireAuth` | routing.md | `<RequireAuth/>` — no props. It reads `useAuth().status` itself: `<FullPageSpinner/>` when `'loading'`, `<Navigate to={'/login?returnTo=' + encodeURIComponent(pathname + search)} replace/>` when `'signedOut'`, `<Outlet/>` when it passes. **Place it only as a layout route with no `path`** (it only means anything if it wraps children). It is a UX gate, not a security boundary — the actual blocking is done by the server | auth gate layout route |
| `RouteErrorBoundary` | routing.md | `<RouteErrorBoundary/>` — no props. It reads the error itself with `useRouteError()`, so it is used **only as a route's `errorElement`** (placed as an ordinary child it has no context). It catches **exceptions during render** and nothing else — a query error reaches it only if that query has `throwOnError: true` | route error boundary |
| `safeReturnTo` | routing.md | **`src/lib/safeReturnTo.ts`** — `safeReturnTo(raw, fallback = '/'): string` — the order is **(the raw value to validate, the replacement path)** with `raw: string \| null` and `fallback` defaulting to `'/'`. It never throws (even a failing `new URL` yields `fallback`). **Blocked → `fallback`**: `//host` · `https://host` · `/\host` · `javascript:` · `/..//host` (cases that become protocol-relative again after normalization). **Passing**: an internal path such as `/tasks/42?x=1#a` comes back as `pathname + search + hash` unchanged. Pass the return value only to `navigate()` — `window.location.assign` bypasses the validation | return-path validation (blocks external URLs) |
| `config` | types-and-testing.md | **`src/config.ts`** — `config: { apiBaseUrl: string; oidc: { authority: string; clientId: string; logoutUrl: string } }` (`as const`) — evaluated at module load (boot), and when `apiBaseUrl` (the API **origin** — the call site appends the path as `/api/...`) is empty it **throws** `Error('Environment variable …')` on the spot. The `oidc` values are `''` when empty and do not throw — the OIDC adapter (`src/auth/session.ts`) checks them at module load and produces the same boot failure. It is the **only module** in which `import.meta.env` appears, and values must be read with literal keys for Vite's static substitution to happen | the only module that reads environment values |
| `assertTask` · `parseTask` | types-and-testing.md | **`src/features/tasks/api/tasks.types.ts`** — `assertTask(v: unknown): asserts v is Task` — an assertion function with no return value; on failure it does `throw new ApiError(500, 'BAD_SHAPE', …)`. `parseTask(v: unknown): Task` — the same check, then it returns the value as is. **The one you pass to `http`'s `parse` option is `parseTask`** (an assertion function returns no value) | narrowing a response — checks all four fields (`id` · `title` · `status` · `createdAt`) |
| `Task` · `TaskStatus` · `TaskFilter` · `CreateTaskInput` | types-and-testing.md | **`src/features/tasks/api/tasks.types.ts`** — `TaskStatus = 'open' \| 'done'` · `Task = { id: string; title: string; status: TaskStatus; createdAt: string }` (the four fields of contract §0 are all of it) · `TaskFilter = { status: TaskStatus \| 'all' }` (`'all'` is dropped from the query string) · `CreateTaskInput = { title: string }` | domain entity types |
| `ApiError` · `ApiErrorCode` · `FieldErrors` | data-fetching.md | **`src/lib/api/errors.ts`** — `new ApiError(status: number, code: ApiErrorCode, message: string, opts?: { details?: FieldErrors; requestId?: string })` — **arguments 2 and 3 are both strings, so only the order distinguishes them: (code, message)**. `status === 0` means no response. `ApiErrorCode` is the 9 codes of contract §4 + the client-only `NETWORK_ERROR` · `TIMEOUT` · `BAD_SHAPE`. `FieldErrors = Record<string, string[]>` (a form-wide error uses the key `_`). `details` · `requestId` are filled by the http layer from the failure envelope (`requestId` comes from the `x-request-id` header when the body lacks it) | error normalization |
| `http` · `Page` | data-fetching.md | **`src/api/http.ts`** — `http.get/post/patch<T>(path, init?)` · `http.delete(path, init?): Promise<void>` · `http.getPage<T>(path, init?): Promise<Page<T>>`. **The body is `init.body` — the second positional argument is not the body.** `init = { body?, signal?, parse?: (v: unknown) => T, auth?: boolean, credentials? }`. It strips the envelope's `data` and returns it, passing it through `parse` when present (`getPage` does so per row). Every failure is thrown as an `ApiError`. On 401: `refresh()` once → the original request once → if the retry is also 401, `endSession()`; with `auth: false` it does neither. `Page<T> = { items: T[]; nextCursor: string \| null }` | HTTP client · the only place for raw fetch |
| `queryClient` | data-fetching.md | **`src/api/queryClient.ts`** — `queryClient: QueryClient` — one for the whole app. Query `retry` is 0 for 4xx · `BAD_SHAPE`, 2 otherwise. Mutations use `retry: false`. **The logout procedure does `cancelQueries()` → `clear()` on this instance** | server cache |
| `listTasks` · `getTask` · `createTask` · `updateTaskStatus` | data-fetching.md | **`src/features/tasks/api/tasks.api.ts`** — `listTasks(filter, cursor?, signal?): Promise<Page<Task>>` · `getTask(id, signal?): Promise<Task>` · `createTask(input: CreateTaskInput): Promise<Task>` · `updateTaskStatus(id, status): Promise<Task>` (`PATCH /api/tasks/:id`, body `{ status }`). All of them pass `parse: parseTask`. Path `/api/tasks`, `limit=20`, the cursor is sent back without being interpreted | endpoint functions |
| `taskKeys` | data-fetching.md | **`src/features/tasks/api/tasks.queries.ts`** — `taskKeys.all` · `.lists()` · `.list(filter)` · `.detail(id)` — hierarchical, so invalidating `lists()` covers every filtered list. **The cursor does not go in the key** | query key factory |
| `useTasksQuery` · `useTaskQuery` · `useCreateTaskMutation` · `useUpdateTaskStatusMutation` | data-fetching.md | **`src/features/tasks/api/tasks.queries.ts`** — `useTasksQuery(filter: TaskFilter)` — one argument. **A `useInfiniteQuery` result**: flatten with `data.pages.flatMap((p) => p.items)`. `isPending` (no data in the cache) and `isFetching` (background refresh) are separate fields, and it has `hasNextPage` · `fetchNextPage` · `isFetchingNextPage`. `error` is an `ApiError`. `useTaskQuery(id)` — a single-record `useQuery`. `useCreateTaskMutation()` → `mutate(input: CreateTaskInput)`. `useUpdateTaskStatusMutation()` → `mutate({ id, status })`. On success both mutations `setQueryData` the detail and invalidate the list | query/mutation hooks |
| `getAccessToken` · `refresh` · `endSession` · `startSession` · `useAuth` · `AuthStatus` | auth-and-session.md | **`src/auth/session.ts`** (variant) — `getAccessToken(): Promise<string \| null>` — never throws. `refresh(): Promise<boolean>` — one refresh; concurrent calls **share the same promise** (single-flight); on failure it sets the status to `'signedOut'` and returns `false`. `endSession(): void` — **for the http layer only**, called when the retry after a refresh is also 401. It clears the local session · cache · stores and sets the status to `'signedOut'` (`RequireAuth` sends the user to login). No network call, never throws. `startSession(): Promise<void>` — called once by `main.tsx` before rendering. `useAuth(): { status: AuthStatus; signIn: (returnTo?: string) => Promise<void>; signOut: () => Promise<void> }` — no arguments. `AuthStatus = 'loading' \| 'signedIn' \| 'signedOut'`. `signOut` owns `cancelQueries` → … → `clear()` → `clearClientState()`. **The http layer calls only `getAccessToken` · `refresh` · `endSession`** | auth adapter |
| `authRoutes` | auth-and-session.md | **`src/auth/routes.tsx`** (variant) — `authRoutes: RouteObject[]` — `routes.tsx` spreads it **outside** `RequireAuth`. Self-issued has `login` only, OIDC has `login` + `auth/callback`. Return navigation is done only by this route's screens, with `navigate(safeReturnTo(…))` | auth routes |
| `handlers` · `renderWithProviders` · `server` | types-and-testing.md | **`src/test/msw/server.ts`** — `server = setupServer(...handlers)` — a test uses `server.use(...)` to override only that test's failure response. `handlers: RequestHandler[]` — an MSW v2 array, and it must honour the **envelope contract** (success `{ data, nextCursor }`, failure `{ error: { code, message, details? }, requestId }`). `renderWithProviders(ui: ReactNode, opts?: { route?: string }): RenderResult & { queryClient }` — the second argument is optional and defaults to `{ route: '/' }`. It creates **a fresh QueryClient per call** (`retry: false`, `gcTime: 0`) — never shared | test harness |

`Component` is out of scope for the ledger — it is a lazy route export whose name React Router dictates, so
a different body per file is normal.

## requires — the seam must supply them

If the seam fails to fill this list, the pack's examples become unrunnable. The gate checks it after assembly.

**Empty from v3.35.0.** `Task` · `http` · `ApiError` · `Page` · `useTasksQuery` are defined by the pack on the premise
of the standard contract (provides above), and `useAuth` is defined not by a library binding but by the auth adapter variant.
A combination whose variant does not resolve, such as a hybrid app shell, generates `auth-and-session.md` but must keep
**the shape of the adapter rows in provides above exactly** — that shape is the contract for what gets generated.
